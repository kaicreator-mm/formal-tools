# Issue #11 / G4 — persistent candidate and fail-closed replay R1

## Engineering deliverable (not Product G4 PASS)

PR #23 shipped in-memory `CANDIDATE` envelopes. This change adds `packages/runner/js/solution-store.mjs`: an owner-provisioned **absolute, local directory**, content-addressed `candidate-<SHA>.json`, same-directory temporary write + file fsync + atomic no-replace hard-link publication + directory fsync on supported POSIX local filesystems, exact readback/integrity check, version/provenance drift rejection, and a non-overwritable revocation tombstone.

Public functions: `persistSolutionCandidate`, `inspectStoredReplay`, `revokeStoredCandidate`. The store accepts original G2 Problem/Method/provenance JSON text, calls `sealSolutionCandidate` and `inspectCandidateReplay`, and never accepts LLM/self-attested `QUALIFIED` or `SUPPORTED_WITH_SCOPE`. All statuses preserve `replay_allowed=false`, `solution_promotable=false`, `claim_result=UNVERIFIED`. Matching live provenance returns `REPLAY_BLOCKED_UNQUALIFIED`, drift returns `STALE`, and tombstone returns `INVALIDATED`. Read/mutation errors return `BLOCKED`.

The store saves **only metadata and content hashes**, not raw private sources or executable commands. A local owner must provision the store directory with appropriate permissions. The API is not an MCP endpoint or a multi-tenant service; it does not provide Host identities, process isolation, cryptographic witness authority, or a signed semantic Oracle. Manual tampering with the filesystem is rejected on readback, but the host itself is not independently attested.

## Independent R1 review repair (P1-G4-01, P2-G4-02)

The prior direct `open(final, "wx") → write` path could expose a partially published final record on crash/concurrent read. The repair writes complete bytes to a private same-directory `.pending-<UUID>` file, syncs the file, atomically hard-links to the final content-addressed name **without replacement**, and syncs the directory. Collision permits idempotent identical bytes only; pre-existing different or corrupt final content is blocked. The temporary name is unlinked on normal completion. Crash before hard-link can leave only a private `.pending` orphan (the owner may audit/remove it), not a visible partial canonical record. Existing partial final files from older versions remain blocked and require explicit owner recovery, never silent clobbering.

**Threat model:** POSIX local filesystem with same-directory atomic hard-link and supported directory fsync, permissioned/owner-controlled directory. Network/remote/mutable-user mount atomicity, power-failure semantics without filesystem/journal guarantees, hostile owner/root process and cross-user isolation are **not claimed**. Directory durability is probed **before** any write: on a platform whose directory fsync is unsupported (EPERM/EINVAL/EOPNOTSUPP/ENOSYS/ENOTTY, verified on win32/NTFS), persist/revoke abort with zero writes — no temp file, no link — and return `BLOCKED` whose issue names the directory-fsync unavailability, the owner's duty to provision a local POSIX-style store directory, and the recovery (nothing was written; provision a supported store and retry). If the probe passed yet the post-publication directory fsync still fails, a distinct `BLOCKED` reports that the record may exist at its final path but is not directory-durable, and the caller must re-inspect via `inspectStoredReplay` or retry persist/revoke before relying on the state. `NEW`/`EXISTING`/`INVALIDATED` with `record_write` are returned only when that operation performed at least one successful directory fsync — the pre-write probe itself is that fsync for idempotent `EXISTING` answers, since it flushes prior directory entries. No fake crash-durable PASS. Revoke checks occur before and after persist publication. A revocation racing after the final check is authoritative for subsequent `inspectStoredReplay` calls; callers must re-inspect when consuming and must never treat `CANDIDATE_PERSISTED` as permission to execute.

R1 focused negatives include concurrently publishing an identical SHA, concurrent same-reason tombstones, permanent revoke→persist→reopen non-resurrection, interrupted temporary-file orphans, partial/corrupt final-path refusal, and no unqualified promotion. All remain synthetic engineering tests, not Source/Model/Host/Oracle formal qualification.
