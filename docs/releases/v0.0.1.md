# formal-tools v0.0.1 — initial consumer release

**State: NOT YET PUBLISHED.** This document defines what to tag as the first `v0.0.1` release once the #180 user-facing integration stack is merged. The published GitHub release notes must be updated to the **actual tagged main SHA** before publishing. Do not interpret the candidate package fields or this Markdown as an existing release.

## Product promise

A small, locally deployable, **trusted-host formal-tool execution layer** for consuming applications. The first integration paths are CLI / local MCP stdio / ESM SDK / local browser and bounded HTTP. These use a shared typed plan and real solver receipts; they are not separate domain correctness engines.

### Confirmed scope to freeze

| Area | v0.0.1 feature | Limit |
| --- | --- | --- |
| Discovery | 36 registry tools, capability/probe evidence | `NATIVE_PROBE_PASS_SCOPED` is not 36 arbitrary typed execution ops |
| Formal execution | Z3 and cvc5 SMT-LIB2 with cross-check; HiGHS typed continuous LP | Native binaries + trusted pinned environment required |
| Planning | Deterministic typed plan/launcher; optional DeepSeek method proposal | LLM cannot emit executable shell, and a method proposal is not execution |
| NL browser | Bounded linear-integer constraint proposal/review/edit/approve/reject/execute | Translation fidelity not proved; provider key required |
| Results | Distinct process, solver, cross-tool, claim fields; receipt and SHA metadata | Bounded display logs may NOT be full streams |
| Integrations | CLI, stdio MCP, JS SDK, loopback Web | No remote multi-tenant/public SaaS or published npm artifact |

### Important exclusions and truthful labels

1. **No universal NL support**; supported NL model subset: bounded integer linear constraints (up to 16 variables, 32 constraints), with explicit assumptions and non-guessed missing bounds.
2. **No exact integer optimum** in the HiGHS LP workflow: the solver handles the **continuous relaxation** only; `LP_RELAXATION_ONLY` after explicit acknowledgement, otherwise `UNSUPPORTED_EXACT_INTEGER_OPTIMIZATION`.
3. **36/36 native fixture evidence is not 36 user-operation proofs**. #24 is the capability expansion owner.
4. A historical native/LLM/browser acceptance receipt is scoped to its runner, environment, source SHA and test setup. `SURROGATE_APPROVED` is not independent human approval.
5. HiGHS versions/scripts from some pre-release Debian portable bundles did not match the repository pin; until a corrected image is independently verified, treat that deployment as **blocked** rather than calling it production-capable.
6. This is a **source/tag distribution** from the monorepo, with private npm workspaces. The old `formal-tools-skill` package/MCP identity is retained for compatibility.
7. The product version `0.0.1` and contract IDs such as `formal-tools/execution-plan/1.0` version **different things**.
8. There is **no top-level LICENSE file** on the inspected repository baseline. Do not claim third-party licensing/redistribution rights unless the owner explicitly supplies an applicable license; this is separate from using the source within the owner's own applications.
